## Задача

Исходный `bochka-api` моделирует биржу с заявками, балансами и PostgreSQL. Для P1 нужна небольшая программа, которую преподаватель запустит и проверит без настройки окружения. Пользователь выбирает Алису или Боба, размещает заявку на BOCH, видит баланс и стакан и может отменить свою активную заявку. Неверное количество, цена, токен или недостаток средств должны давать объяснимую ошибку без изменения состояния.

## Инженерные решения

**Воспроизводимость.** Только стандартная библиотека Python 3.9+, заранее заданы два демо-участника и начальные балансы. Запуск и тесты — по одной команде из README, сеть нужна только между браузером и локальным сервером. Начальное состояние повторяется после перезапуска. Все суммы и количества — целые числа, поэтому нет ошибок округления `float`.

**Проверяемость.** Торговые правила находятся в классе `Exchange`, HTTP-обработчик только переводит запросы и ответы. В тестах ядро создаётся заново; отдельно проверяется HTTP-маршрут. Для рыночной заявки весь необходимый объём и деньги проверяются *до* списания, поэтому отказ не оставляет частичной сделки. Все изменения состояния выполняются под одной блокировкой на сервере. Тесты покрывают успешную сделку, отказ, резерв, отмену и чужую заявку.

**Понятность.** Статусы `NEW`, `PARTIALLY_EXECUTED`, `EXECUTED`, `CANCELLED` показывают судьбу заявки. Лимитная заявка резервирует RUB или BOCH; при исполнении по лучшей встречной цене покупателю возвращается разница между лимитом и фактической ценой. В README дан проверяемый за минуту сценарий с точными остатками. Интерфейс использует тот же API, что доступен через `curl`.

## ИИ-сравнение

Промпт ИИ-помощнику: «Сделай из существующего Python API учебную мини-биржу для практики 1. Нужны лимитная и рыночная заявки, два участника, браузерный интерфейс, README и тест на ошибочный ввод. Как организовать решение?»

Первый предложенный ИИ вариант опирался на исходный FastAPI и PostgreSQL: добавить страницу к существующим маршрутам и запускать всё через Docker Compose. Функции торговли в нём уже были, но для проверки требовались база, миграции и настройка переменных окружения. Он не решал требование курса о самостоятельной папке `students/КрутиковИД/p1/` и запуске тестов одной командой из неё.

Итоговое решение оставляет тематику и основные правила исходной биржи, но переносит минимальный рабочий сценарий в независимую программу на стандартной библиотеке. По чек-листу P1 здесь есть нужная структура, README с реальными запросами и ответами, автоматические тесты с ошибочным вводом, а также этот дизайн. Цена упрощения: данные не сохраняются между запусками и нет административных функций исходного сервиса; для P1 они не требуются.
